# Changelog

This file owns the release history for `django-lux`.

> `django-lux` is the renamed, actively-maintained successor to
> [`django-microsys`](https://github.com/debeski/django-microsys) (now archived).
> Release history prior to v1.0.0 lives in that archived repository.


## v1.8.0

- **CI Package Integrity Guards**: `dlux/tests/test_package_facades.py` now imports committed split-package modules, validates `__all__` exports, model registration, and System Settings form mixins without reading ignored `.xpose/` archives.
- **Report-Aware Project Seeding**: `dlux_seed --log` now creates a linked `user`-category `CREATE` activity row for every seeded project row, with optional fixed `--user-id` and `--scope-id` attribution; the disconnected `seed_activity_log` command is retired.
- **Optional Form Submit Footer**: `dlux/form_base.html` now offers opt-in `form_content` and `form_footer` blocks, with a shared `.dlux-form-footer` rail for submit controls associated through an HTML form ID. The desktop rail uses a page-local layout boundary and the main-content padding offset to meet the global footer without document overscroll or artificial final-field spacing; it returns to normal flow below 768px. Existing `content` overrides remain unchanged.

### Breaking
- **`dlux.constants` Removed**: the root re-export left behind when those constants moved in ~v1.2.0. Import from `dlux.system.constants` instead.
- **No Compatibility Aliases At The Package Root**: `password_validation.py`, `stack_contract.py` and `runtime_contract.py` moved into their packages with no alias at the old dotted path.
- **ScanLink Is Opt-In**: scanning is off until enabled under Extra Features. Deployments already using scan buttons must switch it on.
- **Unreleased Migrations Folded Into 0016**: the former 0017 and 0018, and the homepage/search fields, are all in `0016`. None had shipped (v1.7.1 ends at 0015). Any dev or staging database that already ran them must be rebuilt.
- **Composer Is Required For Inline Updates**: as a running service, not just the deployer. DjangoLux runs unchanged without it when inline updates are off.

### ScanLink
- **Scanner Distribution Centralized**: the installer manifest, permission-gated download and publish flow move out of project-archive. ScanLink works with any dlux project, so the logic belongs here.
- **Opt-In Per System**: stored in `extra_config['scanlink']['enabled']`, edited on the new Extra Features step. While off, no script loads and no scan button renders.
- **Why It Is Opt-In**: the helper probes `localhost:5443`/`:5000`. Without the tray app installed, the browser logs a refused connection per attempt that no `catch` can suppress.
- **Installers Are Protected Assets**: stored as `ManagedAsset` of kind `installer` under `dlux/assets/private/`, with no `MEDIA_URL` address. The download view is the only route to the bytes.
- **Update Card**: checks the workstation's installed version against the published manifest and offers the matching build. Its project-archive presentation is preserved as an introduction plus equal Connection, Installed Version, and Latest Version status tiles; versions rank numerically, so `0.10` outranks `0.9`.
- **Releases Modal**: publish installers from the Extra Features step using `DluxFileInput`, `DluxChoiceSelectorWidget` and the dlux switch. The SHA-256 is computed from the stored file, never typed in.
- **Compact Installer Publishing Form**: Version, Architecture, and a content-height Active switch share one desktop column beside a full-height installer picker; Notes stretches across the row beside Publish. x86/x64 use adjacent compact chips, and text inputs match the System Settings glass style.
- **The Switch Takes Effect On Click**: writes through a superuser-only endpoint rather than waiting for a form save, so installers can be managed without a save-and-reopen detour.

### Settings and Options
- **Canonical Homepage Configuration**: Added `SystemSettings.homepage_config` and a dedicated Homepage step for default, per-user, and anonymous-home behavior; migration `0016` adds inline-safe storage while runtime promotion and save-time synchronization preserve the legacy `home_url`, `public_root_config`, and profile permission mirrors through v1.x.
- **Global Search Settings Step**: Added `SystemSettings.search_config` and a dedicated Global Search step; the runtime now reads `enabled`, `display_mode`, and `include_data` there while mirroring the legacy titlebar keys through v1.x.
- **Localized Global Search Modes**: The Global Search choice selector now renders translated English and Arabic labels instead of fixed English choices.
- **Logging Step Theme And Alignment**: Logging groups now use setup theme surfaces and gutter-free Dlux switches, with responsive per-model action rows aligned correctly in LTR and RTL.
- **Explained Titlebar Language-Switcher Lock**: An unavailable switcher now dims the whole settings card and exposes an English/Arabic Dlux tooltip naming the missing language-count and/or user-override prerequisite.
- **Responsive Profile Settings Rows**: Profile completion, session/device, and activity-feed switches share an auto-fitting row, while first-login Theme, Language, and Font choices use an evenly distributed wrapping flex rail.
- **Themed Language-Font Table Surface**: The per-language default-font table now uses the active setup item background and border tokens instead of leaving its body transparent against the settings modal.
- **Bilingual Notification Field Guidance**: Added English and Arabic inline descriptions for flash position, card size, text size, auto-close timeout, and maximum visible notices.
- **Compact Conditional Settings Rows**: Strong-password minimum length shares a row with inactivity timeout, the public-page sidebar toggle sits with notification badges, and the public-page titlebar toggle sits with the language switcher. Every conditional control retains its own disabled state, tooltip, and master switch.
- **Back To Options From Backup And Restore**: the page is full-screen rather than a modal, so it had no route back except the browser's Back button.
- **Back Links Sit At The Inline End**: right in English, left in Arabic, with the arrow mirrored — a left arrow reads as forward in RTL. Shared `.dlux-back-link` class.
- **New "Extra Features" Settings Step**: home for optional integrations that stay inert until wanted. Reachable from the wizard, the Options tiles and global search.
- **Config Import With A Reviewable Diff**: a new *Import setup file* tile beside Export. The review reuses the permissions widget, with every change unticked by default.
- **Absent Keys Are Left Alone**: the change set reports settings a file does not cover separately, so an older export cannot silently revert everything added since.
- **Import Snapshots And One-Click Revert**: `SystemSettingsSnapshot` records the pre-change export, who applied it and which keys moved, inside the same transaction as the write.
- **Import Is Reviewed Server-Side**: the change set lives in the session and apply re-reads it, so a doctored request cannot introduce a value that was never shown.
- **Theme Picker Location**: new `theme_picker_location` setting — `sidebar_toolbar` (default), titlebar, or hidden.
- **Options Themes Card Hides When Redundant**: it disappears when exactly two themes are allowed and users cannot override.
- **Reset Dialog Prompts**: a second inline-confirm bar in the Options footer re-arms every prompt dismissed with "don't ask again".
- **`dlux.dialogs` Registry**: `register_dismissible_dialog(id=…, label=…)` makes any prompt resettable, with dismissal state in a user preference.
- **Unsaved-Changes Guard On Settings Modals**: closing System Settings with pending edits now prompts instead of discarding. The redundant Options toggle is removed; users dismiss it from the prompt and re-enable it through **Restore prompts**. Opt in elsewhere with `form.dlux_unsaved_guard = True`.
- **Turning A Step Off No Longer Resets It**: disabled controls do not post, and only Sidebar guarded against that. Nav Bar, Notifications and Email rebuilt their configs from nothing.
- **Disabled Options Explain Themselves**: a dimmed dependent carries a tooltip naming the control that turns it on, read from that control's own label.

### Assets and UI
- **Malformed Template Comment Audit**: added `scripts/find_template_comments.py` to find leaking `{# ... %}` and unclosed `{#` comments by file and line, offer confirmed removal, or include valid server-stripped comments with `--include-valid`.
- **Current Component Tutorial Coverage**: Guided tours now discover rendered shell, Setup, Options, report, backup/restore, Control Panel, registration, user, log, section, profile, and generic table components while skipping absent or duplicate targets.
- **Managed Asset Library**: a superuser modal managing reusable `ManagedAsset` images and WOFF2 fonts, with protected branding references and validated uploads.
- **Dlux File Controls**: the asset library is now a field-anchored file-card overlay with translated selected-state copy.
- **Configurable Sidebar Toggle Icon**: Step 5 picks the titlebar toggle glyph from the icon grid. Directional icons mirror in RTL and flip to face the next click.
- **Sidebar Toggle Behaves Like A Control**: it gained a surface, a focus ring, `aria-expanded`/`aria-controls`, and renders its collapsed state server-side so there is no first-paint pop.
- **Icon Picker Extracted Into A Standalone Helper**: opens as a popover, builds its grid lazily instead of on init, and is keyboard-complete with Escape and focus return.
- **Default Theme By Scope**: `Scope.default_theme` is selectable from the system allowlist when scopes are enabled and multiple themes are allowed.
- **Two-Theme Sidebar Toggle**: with exactly two themes allowed, the sidebar indicator switches directly to the other one.
- **Markup Wrappers**: new `{% dlux_table_shell %}`, `{% dlux_card %}`, `{% dlux_alert %}` and `{% dlux_option_card %}` block tags own their shells.
- **Static And Template Trees Reorganised By Feature**: one folder per feature instead of a shared bucket, with templates mirroring static.
- **Server-Side Sticky Helpers**: `sticky_forms_enabled(request)` and `sticky_form_initial()` read the preference, so a project can gate its own forms.
- **Autofill Split Into Two Preferences**: `autofill_from_related` (FK choice fills matching fields) and `sticky_forms` (a new form reuses your last entry).

### Search and discovery
- **App Options Cards Are Searchable**: cards registered with `register_card()` were invisible to global search. `search_keywords=(…)` adds match terms beyond the title.
- **Deep-Linkable Admin Panel**: `data-options-deeplink` is an addressing hook separate from `data-options-card`, which drives drag-reordering.
- **Form Pages In The Sidebar Builder**: an `add` page is now pickable behind a *Show form pages* toggle. `dlux_exclude`/`dlux_include` override discovery per view.

### Updater and deployment
- **Release Manifest Schema 2**: states facts — `migrations.effect`, `rollback_compatible`, `install.inline`, and a `requires` block — and lets the updater derive admission. Schema 1 still validates.
- **`install.inline` Is A Permission, Not An Override**: a destructive migration is refused inline even when the author allowed it. Unknown values and unknown `requires` keys fail closed.
- **Composer Is Expressible As A Requirement**: `requires.services` carries it. Schema 1 had no way to state a service dependency.
- **Inline-Update Floor Is Computed** from published tags rather than carried by hand. This caught a real gap: v1.2.7 required a rebuild and no release since declared it.
- **Inline Updates Are Performed By Composer**: an approved apply or rollback writes a `package-update-request.json` intent that Composer stages, activates and health-gates from outside the container.
- **Update Checks Are Performed By Composer Too**: `_process_check` no longer reaches PyPI from inside the container.
- **Runtime-Volume Contract Published**: `dlux/contracts/runtime.*` and `manage.py dlux_runtime_contract` describe the runtime volume as a machine-readable contract.
- **Unusable Runtime Volume Is Caught Before The Click**: enabling inline updates without a writable runtime volume used to offer an Update button that could not work.
- **`dlux-updater` Service Retired; Composer Owns Boot**: generated projects declare `pre_start` init containers for runtime reconcile and migrations, and the entrypoint waits on `migrate --check`.
- **`enable-updater` Deprecated**: it now prints the migration path and its removal release.
- **Scaffolded `compose.dev.yml` Disables Inline Updates**: dev stacks inherited `DLUX_INLINE_UPDATES_ENABLED=True` from the shared anchor and could apply a real update to a source checkout.

### Structure
- **Six Root Modules Split Into Packages**: `forms`, `models`, `reports`, `discovery`, `backup` and `translations` are now packages, each re-exporting its full public surface from `__init__.py`.
- **`api.py` Split By Security Boundary**: five modules behind a façade — introspection, preferences, system config, dialogs and health.
- **`scaffold.py` Split**: `project.py`, `app.py`, `legacy.py` behind a façade, with templates colocated at `dlux/scaffold/templates/`.
- **Auth Domain Grouped Into `dlux/auth/`**: registration, password reset, password validation, login throttling, trust and session history.
- **Destructive Admin Actions Grouped Into `dlux/admin_actions/`**: data reset and force-password-change are irreversible, superuser-gated and audit-logged, so they are read and tested as a pair.
- **`SystemSettingsForm` Split Into Group Mixins**: 84 methods and the crispy layout moved into 14 mixins under `dlux/forms/system_settings_groups/`.
- **`views/general.py` Renamed To `views/options.py`**: nothing in it was general — it serves `sys/options/`. `global_search_view` moved to `dlux/views/search.py`.
- **Setup Wizard JavaScript Split**: `setup/js/main.js` went from 5,047 lines to 2,783 across ten modules, with unit, functional and load-order contract tests.

### Fixed
- **Mobile Global Search Crowded The Titlebar**: Below 768px, the configured always-visible search now reverts to its icon; activating either search mode opens the field and results below the sticky titlebar, and resizing an open desktop field to mobile collapses it safely.
- **Opaque Sticky Translation Header**: The translation matrix now layers its themed header gradient over the opaque theme row surface, preventing scrolling translations from bleeding through the stuck header.
- **No Setup Chrome In Individual Settings Modals**: Options now opens each System Settings step directly on its editor; the localized overview and numbered step badges remain exclusive to the first-launch setup page.
- **Tutorial Ignored The Display Language**: step text requested keys without their `tut_` prefix and the control bar read a nonexistent `window.TUT_STRINGS`, so both fell through to English. The tour now uses the page's resolved `window.DLUX_STRINGS`, ships current English/Arabic copy, and follows document direction.
- **Backup Page Scroll Escaped Its Pane**: layout containment keeps the Backup & Restore grid inside `#mainContent`; `backup_page.test.mjs` now checks the document scroller and a final wheel gesture.
- **Setup Wizard Step Nav Was Off By One**: the Email panel had no button, so every later button opened the wrong panel and Backups was unreachable.
- **Admin Panel Command Rail On Small Screens**: The collapsed rail no longer reserves hidden width or animates layout width. The open rail stays beside the title from 768px upward, while mobile receives a full-width second row with horizontal scrolling.
- **Config Import Rows Showed Raw Keys**: translated group headings sat over rows labelled `email_config`, which read as English on an Arabic install.
- **The Import Review Rendered Inside The Options Card**: it never reached a modal, distorting the page. The dynamic modal is URL-driven and expects a JSON payload.
- **The Titlebar Search Box Loaded Pre-Filled With A Saved Username**: Chrome ignores `autocomplete="off"` when picking a username field for a password input that has none before it.
- **Slow Page Renders**: template wrapper tags built a new `RequestContext`, re-running every context processor, and `get_available_fonts()` ran a query per call.
- **Bootstrap-From-Empty Install On PostgreSQL**: a swallowed `ProgrammingError` left the transaction aborted, so the next unrelated statement failed and the traceback blamed the wrong operation.
- **dlux Could Half-Build A Project's URLconf**: resolving a URL while `ROOT_URLCONF` was mid-import made Django cache a half-built module and fail every URL check.
- **Package Requests Never Executed On Agent-Only Stacks**: a stack running `composer-agent` without `composer-executor` processed the image trigger but not the package trigger.
- **Email Settings Turned Themselves Back On**: `clean_email_config()` rebuilt the group from flat fields that are disabled, and disabled fields do not post.
- **Autofill And Sticky Forms Were Dead Since v1.5.10**: the helper injected its toggle into a titlebar selector that no longer existed and returned early.
- **Email Actions Stayed Clickable While The Step Was Off**: disabling the step disabled its named fields, but a plain button has no field name to disable.
- **Search Results Were Dead On Click**: the dropdown dispatched its event on `document` while the modal helper listened on `document.body`.
- **Options Deep Link Ignored The Tabs Layout**: the target card sat in an inactive pane, so a result scrolled to nothing.
- **Orphaned Progress Percentage**: the backup and restore tables joined percentage and status into one text run, so it wrapped onto its own line.
- **Asset Library Search Icon Overlapped Its Text**: a global `.glass-input` padding rule with `!important` beat the field's own padding.
- **Sticky-Forms Switch Needed Two Clicks**: the helper reloaded the page immediately after calling `updatePreferences`, cancelling the request in flight.
- **Unsaved-Changes Prompt Opened Under The Modal**: Bootstrap gives every modal the same z-index and does not restack them.
- **Language-Font Table Striped**: theme stylesheets stripe every bare `.table`, ignoring the zebra setting. Added `.dlux-no-zebra`.
- **Nav Bar Builder Was Fed The Sidebar Catalog**: its route list came from `self.sidebar_catalog`, so the hierarchy could never offer anything else.
- **Broken Template Include In project-sales-crm**: `dlux/includes/messages.html` moved during the template reorganisation and both public-catalog editions still referenced the old path.
- **29 Untranslated Strings**: titlebar user-hub styles, file-input labels and every scan status message referenced keys that existed in neither catalogue.
- **Translation Coverage Is Enforced**: `test_translation_coverage.py` fails when a referenced key does not resolve in every language.

## v1.7.1
- **Migrator Has A Written Contract**: `-mm` forces makemigrations for every target app then migrates; bare runs makemigrations only for apps with no `migrations/0001_*.py`; the new `-nm` skips makemigrations and migrate but still collects static. `-mm` and `-nm` are mutually exclusive. The old "has migrations" test accepted any non-`__init__` module, so a helper left in `migrations/` made an unmigrated app look migrated.
- **Fixed: Per-App makemigrations Broke Cross-App Changes**: `makemigrations` ran in a loop, one app at a time, resolving each app's dependencies against a half-written migration graph. It is now a single call carrying every selected label.
- **Fixed: collectstatic Ran Before Migrations**: `collectstatic --clear` was the first step and raised on failure, so a static problem meant migrations never ran at all. It now runs after `migrate`, and a run that skips migrations still collects.
- **Unrelated Setup Steps No Longer Fail Deploys**: `populate`, superuser creation, and the first-launch config bootstrap warn and continue, summarized at the end; `makemigrations`, `migrate`, `collectstatic`, and `dlux_setup` stay fatal. A read-only `migrations/` directory is refused up front instead of failing mid-generation, and a `--noinput` makemigrations failure names the likely cause.
- **Migrator Runs Once Per Start**: The scaffold declares it as an `org.dlux.post-start` label instead of a Compose `post_start` hook. Compose ran that hook itself, unflagged, while composer separately ran its own flagged copy — two migrators overlapping, one `collectstatic --clear` wiping `STATIC_ROOT` under the other. Needs composer >= 1.3.5, which reads the label; `composer check --fix` migrates deployed projects.
- **Fixed: Truncated `.dlb` Upload Blamed The File**: A large backup upload is cut off by the reverse-proxy body limit (`CADDY_MAX_SIZE`/`NGINX_MAX_SIZE`, `10M` by default), so Django gets no complete multipart part and `request.FILES` is empty — which hit the first branch in `system_backup_upload_view` and reported `backup_upload_invalid` before the size check ever ran. That path is now its own `backup_upload_incomplete` error naming the proxy limit and the copy-into-`dlux_backups/` route.
- **Configurable Upload Cap**: `DLUX_DLB_UPLOAD_MAX_MB` replaces the hardcoded 512 MB `DLB_UPLOAD_MAX_MB_DEFAULT`, read per request via `_dlb_upload_max_mb()`. The Backup & Restore page now states the copy route under the upload form.
- **Restore Progress**: Restore reported nothing but a `running` badge. Migration `0015` adds `progress_percent`/`progress_message`/`stage`/`heartbeat_at` to `SystemRestore`, and `run_system_restore` reports decrypt bytes, per-model load, per-file writes, and finalize across a 0-100 span. The restore table gains the backup table's progress bar and a `system_restore_list_status` poller.
- **In-Transaction Progress Mirror**: The database phase runs in one transaction, so a row UPDATE from inside it is invisible until commit — exactly the longest stretch. `set_restore_progress()` mirrors every tick into the cache and `read_restore_progress()` overlays it on the row, never moving backwards. The row stays authoritative, so progress survives a reload, a worker handoff, and an unshared cache.
- **Restore Notification**: A terminal `restore_completed`/`restore_failed` drawer notice is emitted after the transaction commits. There is deliberately no start notice: a restore wipes and reloads `DluxNotification`, so an item created beforehand would be deleted by the restore itself.
- **Fixed: Time-Only Throttle Dropped Fast Phases**: `RestoreReporter.tick()` now writes when the displayed percentage advances *or* the interval elapses. A purely time-based throttle silently dropped every phase completing inside one interval, so a fast restore reported no decrypt step at all.

## v1.7.0
- **SMTP Timeout Is A Setting, Not An Env Var**: The Email step gains an **SMTP timeout (seconds)** field, so an operator can widen it for a slow provider from the UI instead of editing compose and recreating the relay. One number is exposed, not two: for relay transport it is the relay's upstream budget and the app's client timeout derives as that plus 15s headroom, so raising it can never invert the ordering the 451 error reporting depends on; for direct transport it is the client timeout outright. Blank keeps the shipped default, values are clamped to 5-300s, and changing it does not revoke verification — it is an operational knob, not part of the connection a test send proved.
- **Fixed: Email Group Reset On Other Steps' Saves**: `email_config` is a model field, so `Meta.fields` put it ahead of the declared-only `email_config_*` scalars in clean order — `clean_email_config()` packed the group before those scalars were cleaned and read empty defaults, resetting `timeout` and `enabled` whenever any *other* settings step was saved. Packing now falls back to the stored value whenever a scalar has not been cleaned yet, so it is independent of the order Django picks.
- **Send-Test Control Is One Input Group**: The recipient field and its Send-test button were two grid columns, which can never stay level — the field column carries a label and help text, so it is taller, and any vertical alignment picks the wrong edge (`end` drops the button below the input, `start` lifts it above). They are now a single Bootstrap input-group, level by construction regardless of the text around them, with the help and result lines below the whole control.
- **Composer Owns The Entrypoint Migration**: `stack_contract.json` (schema 2) now records each dlux-owned service's `command_module` plus a `retired_command_modules` map, and `stack_contract.py` gains `diff_command_modules()` / `fix_command_modules()`. `composer check --fix` can therefore detect and repair a project still invoking `tools.smtp_relay` or `tools.dlux_runtime_supervisor`, instead of the Compose file needing a manual edit or a dlux subcommand — Composer owns the Compose file, so it owns this.
- **Email Has A Permanent Service Indicator**: The Options → System panel's Email row no longer renders only while public registration or email 2FA is on. Those are the settings that are locked until email is verified, so the indicator was hidden exactly when it was needed. It now always shows, reports four distinct states — off, unavailable, configured-but-unproven, verified — and gains a recheck control like Tasks. The recheck re-reads configuration and verification only; it never sends mail (that stays the Email step's test button).
- **SMTP Relay Ships In dlux**: The internal relay moved out of the per-project `tools/smtp_relay.py` scaffold file into the package as `python -m dlux.smtp_relay`, mirroring the runtime supervisor. Fixes to it now arrive with dlux instead of being stranded in whatever copy a project was scaffolded with — the timeout and failure-reporting work in this release was invisible to already-generated projects for exactly that reason. New scaffolds emit the packaged command; `dlux enable-updater` rewrites an existing project's `smtp-relay` command in place (idempotent). The retired template is archived under `.xpose/`. **No configuration changes**: the `SMTP_RELAY_*` environment contract and the UI-managed `email_config` are untouched, and the relay remains stateless. Being a real module also makes it testable — 16 new tests cover the protocol loop, dot-stuffing, size limits, DB-vs-env config resolution and the 451 reason, none of which could be asserted while it was template text.
- **Email Step Layout And Post-Test Unlocking**: A successful test now unlocks the mail-dependent toggles in place. The lock is rendered server-side, so inside an already-open modal they stayed greyed out until a reload, which read as the test having done nothing — the backend was persisting verification correctly all along. The step's columns moved from `col-lg-*` to `col-md-*` (at `lg` they wrapped inside the modal, dropping the Send-test button onto its own row below the recipient field), the SMTP password and failure-recipient fields now share one row, and the `Email service: <reason>` banner became an inline status beside Apply instead of a full-width alert. The write-only password field now states when a secret is already stored, so a blank box is not mistaken for a lost password.
- **Apply And Test Email In One Pass**: The Email step gains an in-form **Apply email settings** button (`POST sys/settings/email/apply/`, superuser-only) that persists just `email_config` without closing the modal, so an admin can enter SMTP details and send a test without saving, reopening and navigating back. The test send still uses the *stored* config on purpose — the SMTP relay is a separate container that reads config from the database, so testing unsaved form values would exercise something the relay cannot see. The form binds in single-step mode for the Email step, so every other step keeps its stored values and only the email group is written.
- **Verification Survived Saving The Email Step**: The step's save built `email_config`, normalized it, and only *then* attached the encrypted password — so the verification fingerprint covered an empty secret while the stored config held the real ciphertext. Every save therefore revoked verification on the next read and silently re-locked all mail-dependent toggles. Both packing sites now attach the secret before the final normalize. Re-arming on a real connection change (host, port, or a retyped password) is unaffected.
- **Test-Send Shows A Spinner In The Button**: The 'Sending…' line is replaced by an in-button spinner, and the recipient/button row is bottom-aligned so the button no longer sits below the field.
- **Undecryptable SMTP Secrets Are Named, Not Silent**: `decrypt_email_secret()` returned `''` on every failure, making "password encrypted under a different SECRET_KEY" indistinguishable from "no password set" — the send then failed deep in SMTP (or in the relay sidecar) naming neither. Added `strict=True` plus `email_secret_state()` (absent / ok / undecryptable), and the test-send now returns a 409 explaining that the stored password was saved under a different key and must be re-entered. Common causes: a rotated key, or a sidecar container started with a different `DJANGO_SECRET_KEY` than the web service that saved it.
- **Relay Mail Failures Report Why**: The app's SMTP client timeout is now transport-aware — 30s direct, 75s for internal-relay transport — and the scaffolded relay's upstream attempt is a configurable 60s (`SMTP_RELAY_UPSTREAM_TIMEOUT`), sized so the relay still loses the race. Defaults target a **slow** upstream on purpose: servers that scan mail in-line answer connect/EHLO/AUTH instantly and then take 30-60s on DATA, so a handshake-sized timeout looks healthy until the message body and then fails every send, indistinguishable from an outage. Relay delivery is two hops and only the relay can see why the provider hop failed; with the app timing out first, every relay failure surfaced as an uninformative `Connection unexpectedly closed: timed out` while the real cause sat in the relay log ~20s later. The relay now loses the race by design and answers `451 Relay delivery failed: <reason>`, so the actual SMTP error reaches the operator. Reasons are folded to a single 180-char line (an SMTP reply cannot contain CR/LF).
- **Email Gets Its Own Setup Step**: SMTP configuration moved out of Access & Security into a dedicated **Step 3: Email**, placed *before* Access & Security because so many options there depend on mail. The step is optional behind an `email_config.enabled` toggle (same idiom as the Nav Bar step), and its fields now follow that toggle instead of appearing at the top of the security step whenever public signup or email 2FA happened to be on. Options → System Settings gains a matching Email tile, and settings search deep-links to it.
- **A Test Send Is Now The Guard**: `email_config` gained `enabled`, `verified`, `verified_at`, and `verified_fingerprint`. A successful `sys/settings/email/send-test/` records verification against a fingerprint of the exact connection it ran over; a failure clears it. Because `normalize_email_config()` recomputes that fingerprint, every write path — form save, import, `config.json` bootstrap — re-arms verification when a connection field changes, so a stored flag can never vouch for an untested server. Exports drop it: one host's result is meaningless on another.
- **Mail-Dependent Settings Lock Instead Of Clearing**: `email_2fa`, `forgot_password_enabled`, `public_registration_enabled`, and the notification email toggles are disabled with a hover tooltip until email is enabled *and* verified. Locking uses Django's `disabled=True`, which keeps the stored value, so upgrading or editing SMTP can never silently switch off someone's 2FA or password recovery. Runtime sending is unchanged — `get_email_service_status()` still gates delivery, so deployments configuring SMTP purely through env vars keep working untouched. Local debug backends unlock without a test send.
- **Email Step Uses The Shared Toggle Card**: The step's **Enable email delivery** switch renders as the standard Dlux toggle card like the Sidebar/Nav Bar step switches, not the compact bare checkbox reserved for the inline TLS/SSL fields. A new **optional** `highlights` array in the release manifest (validated/normalized in `manifest.py`: list of strings, trimmed, ≤160 chars each, ≤8 items; fully back-compatible — older manifests omit it, older updaters ignore it) supplies per-release bullets, and the UI **always** appends a generic "Bug fixes and improvements" entry last (even when a release ships no highlights). List height is capped with scroll (`.dlux-update-highlights`).
- **Image-Level Update Orchestration**: The updater now handles releases that require a full project **image rebuild** — the case the inline wheel updater detects (`latest_compatible=False`, "Project image rebuild required") but cannot apply. New `DluxImageUpdate` model + `UpdateService.tick_image_update()` lifecycle (driven from the existing update-worker loop) runs a pre-update backup (reusing `_create_backup`/backup modes), enters maintenance mode, writes a trigger for the external **composer-updater** (which pulls the new image, runs its version gate, recreates the containers, and runs `migrator`), and finalizes the run by reading composer's `deploy-status.json`. Deliberately **separate** from the `DluxUpdateRun` inline worker/recovery so the wheel-update path and its boot-time interrupt recovery are untouched (a naive reuse would false-fail every hand-off, since composer recreates the updater container mid-run). Reuses `DLUX_UPDATE_CHECK_INTERVAL` detection, `set_maintenance`, and the backup subsystem. Migration `0008_dluximageupdate` (single additive CreateModel; inline-safe). New endpoint `POST sys/api/dlux-update/image/` (superuser + current-password guarded) and image-update availability/status fields on `sys/api/dlux-update/state/`. **Options → Updates UI**: an "Update (image rebuild)" button appears when an image-rebuild release is available, reusing the existing review modal (password + backup-mode) with a stronger maintenance warning; since the recreate takes the page into maintenance, progress is tracked best-effort by polling the state endpoint's `image_update` object (status + composer `deploy_status`) and the final result surfaces on the next successful load.

## v1.3.0

- **Permission Groups / Presets (Reusable Permission Bundles)**: Adds named, reusable permission **presets** so admins/staff stop hand-picking permissions per user. ## v1.0.0

- **Rebrand from django-microsys**: First release under the `django-lux` name
  (import package `dlux`). Feature-equivalent to `django-microsys` 2.4.1 — the
  full system/runtime framework (first-launch setup wizard, user & security
  operations, four-tier staff authorization, multiple 2FA flows, scopes, audit
  logging, dynamic modal CRUD, reports/overview, and the encrypted full-system
  backup) carries over with identical behavior. The package imports as `dlux`,
  the Django app label and database tables use the `dlux_*` prefix, project
  configuration lives under `DLUX_CONFIG` (`from dlux.utils import
  dlux_settings`), the scaffolding CLI is `dlux` (`python -m dlux startproject`),
  and the system backup format is `.dlb` (`DLB1`, kind `dlux-system-backup`)
  with the standalone `tools/dlb-viewer` reader. The 545 internal `ms-` CSS
  classes were renamed to `dl-`; the optional SSO companions are
  `django-lux-sso` / `django-lux-sso-client` with OIDC claims `dlux_sso_role`
  and `dlux_sso_client_id`. Migrations are squashed to a fresh `0001_initial`.
- **In-place migration from django-microsys**: Added the
  `dlux_migrate_from_microsys` management command that converts an existing,
  fully-migrated `django-microsys` 2.4.1 database to `django-lux` without data
  loss — renames every `microsys_*` table to `dlux_*`, repoints
  `django_content_type` (so permissions follow automatically), collapses the
  recorded migration history to dlux's `0001_initial`, and rewrites
  app-label-qualified `UserActivityLog.model_key` values (`microsys.*` →
  `dlux.*`). Dry-run by default; pass `--yes` to apply. See
  [docs/migrating-from-microsys.md](docs/migrating-from-microsys.md).
